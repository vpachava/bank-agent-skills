## Question

Build the `documentation/` category — **6 invoke-and-act skills**, each `documentation/<name>/SKILL.md` on the locked archetype (ticket 01):

1. **executive-summary** — produce an exec summary (business case, outcomes, risk headlines) for a banking initiative; produce the summary.
2. **proposal** — author a solution proposal (problem, approach, scope, cost/timeline, options); produce the proposal.
3. **raid-log** — maintain/author a RAID log (Risks, Assumptions, Issues, Dependencies) for an initiative; produce the RAID log.
4. **risk-register** — author/maintain a risk register (risk, owner, likelihood/impact, treatment) banking-aware; produce the register.
5. **project-charter** — author a project charter (scope, objectives, stakeholders, governance) for a banking initiative; produce the charter.
6. **design-document** — author a design document (context, options, design, NFRs, risks) for a banking solution; produce the design doc.

Each skill: frontmatter + per-skill metadata; embedded banking checklists (regulatory language, audit-friendly framing, governance audience); Banking pitfalls (vague ownership, stale registers, exec-doc reg-debt); Outputs (named); Related skills cross-linked — `../governance/risk-register`-style cross-links to `../governance/architecture-board`, `../architecture/architecture-decision-records`, `../discovery/stakeholder-workshop`. These are mostly lighter/content skills — keep depth in the band.

Output = 6 skill files in `skills/documentation/`. Resolution comment names files, close, Decisions-so-far pointer.
